## 1. ФИЛОСОФИЯ

### Было (классическое веб-приложение):
```
Пользователь → нажимает кнопки → API выполняет → ИИ помогает
```
ИИ — вспомогательный инструмент. Пользователь — оператор.

### Стало (AI-Agent-First):
```
ИИ-Агент «Бухгалтер» → наблюдает, думает, действует → API/сервисы — его инструменты
Пользователь → подтверждает решения, задаёт вопросы, смотрит отчёты
```
ИИ — центральный мозг. Пользователь — руководитель, которому агент отчитывается.

## 3. AI AGENT SERVICE — ЯДРО СИСТЕМЫ

### 3.1. Что такое AI Agent

AI Agent — это **автономный сервис**, который:
1. **Наблюдает** за событиями (новый файл, новая операция, приближение срока)
2. **Анализирует** через LLM (Claude Sonnet) с полным контекстом бизнеса
3. **Действует** через Tool Functions (вызывает парсеры, API, расчёты)
4. **Отчитывается** пользователю (уведомления, дашборд, чат)

### 3.2. Agent Loop (основной цикл)

```python
class AgentLoop:
    """
    Основной цикл ИИ-агента.
    Запускается по событиям (event-driven) и по расписанию (scheduled).
    """
    
    async def run(self, trigger: AgentTrigger) -> AgentResult:
        """
        1. OBSERVE  — собрать контекст: что произошло? что изменилось?
        2. THINK    — отправить в LLM с инструментами, получить план действий
        3. ACT      — выполнить tool calls (парсинг, расчёт, API-запросы)
        4. REPORT   — сформировать отчёт, уведомить пользователя
        """
        
        # 1. Observe
        context = await self.observe(trigger)
        
        # 2. Think + Act (LLM с tool calling)
        result = await self.think_and_act(context)
        
        # 3. Report
        await self.report(result)
        
        return result
```

### 3.3. Триггеры агента (что запускает цикл)

| Триггер | Описание | Пример |
|---------|----------|--------|
| `EVENT_FILE_UPLOADED` | Загружен новый файл | Пользователь загрузил выписку банка |
| `EVENT_NEW_BANK_DATA` | Получены данные из банка | API Сбера вернул новые операции |
| `EVENT_NEW_OFD_DATA` | Получены данные из ОФД | Новые чеки за день |
| `EVENT_NEW_EDO_DOCUMENT` | Получен документ из ЭДО | Входящая счёт-фактура |
| `SCHEDULE_DAILY` | Ежедневная проверка | 09:00 каждый день |
| `SCHEDULE_WEEKLY` | Еженедельный отчёт | Понедельник 09:00 |
| `SCHEDULE_PRE_DEADLINE` | За N дней до срока | За 14/7/3/0 дней до сдачи |
| `USER_QUESTION` | Пользователь задал вопрос | "Сколько я должен по НДС?" |
| `USER_CONFIRMATION` | Пользователь подтвердил/исправил | Подтвердил классификацию операции |

```

ПРАВИЛА:

2. При неоднозначности — запрашивай подтверждение пользователя
3. Объясняй простым языком (не бухгалтерским жаргоном)
4. Всегда проверяй: ИНН, суммы, соответствие НДС

{tools_description}

При обработке событий следуй паттерну:
1. Определи что произошло
2. Оцени влияние на учёт
3. Выполни необходимые действия через инструменты
4. Сообщи пользователю о результатах и если нужно — запроси подтверждение
```

## 4. EVENT-DRIVEN АРХИТЕКТУРА

### 4.1. Поток событий

```
Файл загружен ──────────┐
Данные из банка API ─────┤
Документ из ЭДО ─────────┤
Чек из ОФД ──────────────┼──► Event Bus (Redis) ──► Agent Loop ──► Tools
Cron (расписание) ───────┤                                         │
Пользователь (чат) ──────┤                                         ▼
Подтверждение юзера ─────┘                                   БД + Уведомления
```

### 4.2. Модель событий

```python
class AgentEvent:
    event_type: AgentTriggerType  # тип триггера
    user_id: UUID                 # для какого пользователя
    payload: dict                 # данные события
    priority: int                 # приоритет (0=low, 10=critical)
    created_at: datetime
```

### 4.3. Очередь событий

- **Высокий приоритет:** Файл загружен, подтверждение пользователя, вопрос в чат → обработка немедленно
- **Средний приоритет:** Новые данные из API, ежедневная проверка → обработка в очереди
- **Низкий приоритет:** Еженедельный отчёт, анализ → обработка в фоне

## 7. OPENROUTER + TOOL CALLING

### 7.1. Как работает

Мы используем **OpenRouter API** с поддержкой **tool calling** (function calling):

```python
# Агент отправляет в LLM:
messages = [
    {"role": "system", "content": system_prompt},
    {"role": "user", "content": f"Событие: загружен файл {filename}. Обработай."}
]

tools = [
    {
        "type": "function",
        "function": {
            "name": "recognize_document",
            "description": "Распознать документ через OCR + ИИ",
            "parameters": {
                "type": "object",
                "properties": {
                    "file_id": {"type": "string", "description": "ID файла"}
                },
                "required": ["file_id"]
            }
        }
    },
    # ... другие инструменты
]

# LLM отвечает tool_call:
# {"name": "recognize_document", "arguments": {"file_id": "abc123"}}

# Агент выполняет tool call и возвращает результат LLM
# LLM анализирует результат и решает что делать дальше
```

### 7.2. Multi-step reasoning

Агент может выполнить **цепочку действий** за один цикл:

```
1. LLM: "Вижу новый файл. Давай распознаю."
   → tool_call: recognize_document(file_id="abc")
   
2. LLM: "Это счёт-фактура от ООО «Техно». Проверю ИНН."
   → tool_call: query_egrul(inn="7712345678")
   
3. LLM: "ИНН валиден. Добавлю в книгу покупок и уведомлю."
   → tool_call: add_to_purchase_book(document_data={...})
   → tool_call: send_notification(message="Обработан УПД от ООО Техно, НДС 22 000₽")
```

## 8. БЕЗОПАСНОСТЬ АГЕНТА

### 8.1. Ограничения

- Агент **НЕ может** отправлять декларации в ФНС без явного подтверждения пользователя
- Агент **НЕ может** совершать финансовые операции (только анализ)
- Агент **НЕ может** удалять данные — только помечать
- Все действия агента **логируются** в `agent_action_log`

### 8.2. Уровни автономности

| Уровень | Действие | Требует подтверждения? |
|---------|----------|----------------------|
| 🟢 Авто | Классификация операций (уверенность >90%) | Нет |
| 🟢 Авто | Распознавание документов | Нет |
| 🟢 Авто | Сверка данных | Нет |
| 🟡 Полу | Классификация (уверенность 70–90%) | Да, запрашивает |
| 🟡 Полу | Формирование КУДиР | Показывает для проверки |
| 🔴 Ручное | Отправка декларации | Обязательно |
| 🔴 Ручное | Подпись ЭЦП | Обязательно |
| 🔴 Ручное | Классификация (уверенность <70%) | Обязательно |
