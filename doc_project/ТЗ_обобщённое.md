# Обобщённое техническое задание
## «ИИ-Бухгалтер» — автоматизированная система налогового учёта для ИП на УСН + НДС

**Версия:** 1.1 (+ AI Agent-First Architecture)  
**Дата:** 27.02.2026  

---

## 1. ОБЩЕЕ ОПИСАНИЕ

### 1.1. Назначение системы
Веб-приложение с мобильной адаптацией, которое автоматически собирает данные о продажах, закупках и банковских операциях, классифицирует их с помощью ИИ и формирует полную налоговую отчётность для ИП на УСН «Доходы минус расходы» + НДС.

### 1.2. Целевая аудитория
- ИП без штатного бухгалтера
- Малый бизнес (розничная торговля, услуги)
- Предприниматели на УСН + НДС (ставка НДС 22% с 2026 г.)

### 1.3. Ключевая ценность
Предприниматель просто работает (продаёт, закупает, платит), а система автоматически:
- Собирает данные из банков, касс, ЭДО
- Классифицирует операции (доход/расход/личное)
- Ведёт книги учёта (КУДиР, книга покупок, книга продаж)
- Рассчитывает налоги (УСН, НДС, НДФЛ, взносы)
- Формирует декларации в формате XML ФНС
- Напоминает о сроках сдачи и оплаты

**Результат:** 15 минут в неделю вместо часов работы с бухгалтером.

### 2.3. Модуль ИИ-классификации операций

#### 2.3.1. Категории входящих платежей

**ДОХОДЫ:**
- Выручка от продаж (оплата от покупателей)
- Поступление по эквайрингу (сверка с ОФД)
- Поступление по POS-кредиту
- Возврат от поставщика (корректировка расхода)
- Прочие доходы

**НЕ ДОХОДЫ:**
- Взнос собственных средств ИП
- Перевод между своими счетами
- Получение кредита
- Ошибочное зачисление

#### 2.3.2. Категории исходящих платежей

**РАСХОДЫ:**
- Закупка товара
- Аренда
- Зарплата
- Налоги и взносы
- Комиссия банка
- Коммунальные услуги
- Транспорт/доставка
- Реклама
- Проценты по кредиту
- Прочие расходы

**НЕ РАСХОДЫ:**
- Снятие на личные нужды ИП
- Перевод между своими счетами
- Погашение тела кредита (проценты — расход!)
- Выдача займа

#### 2.3.3. Логика работы

1. **Первичная классификация** — по назначению платежа, ИНН контрагента, сумме (модель: Claude 3.5 Haiku — быстро и дёшево)
2. **Сопоставление** — связывание банковской операции с документом из ЭДО или чеком из ОФД
3. **Выделение НДС** — из счёт-фактуры, УПД или расчётным путём
4. **Проверка на дубли** — одна продажа не учитывается дважды (касса + р/с)
5. **Запрос подтверждения** — если уверенность < 80%, система спрашивает пользователя

#### 2.3.4. Интерфейс подтверждения

Карточка с данными операции + предположение ИИ + кнопки:
- «Да, верно»
- «Нет, это другое» (выбор из списка)
- «Указать вручную»

### 2.4. Модуль налогового учёта

#### 2.4.1. Книга доходов и расходов (КУДиР)

- **Формат:** по приказу ФНС от 07.11.2023 № ЕА-7-3/816@
- Автоматическое заполнение на основе классифицированных операций
- Колонки: №, Дата, Документ-основание, Содержание операции, Доход, Расход
- **Выгрузка:** Excel, PDF, XML

#### 2.4.2. Книга покупок (входящий НДС)

- Формируется из: счетов-фактур (ЭДО), загруженных XML/сканов, данных «Мой Склад»
- Колонки: №, Дата, Поставщик, ИНН, № счёт-фактуры, Сумма без НДС, НДС, Итого
- **Формат:** по новым формам 2026 года (ставка НДС 22%)

#### 2.4.3. Книга продаж (исходящий НДС)

- Формируется из: данных ОФД (чеки с НДС), выставленных счетов-фактур через ЭДО
- Колонки: №, Дата, Покупатель, Сумма без НДС, НДС, Итого

#### 2.4.4. Расчёт налогов (автоматический по итогам периода)

| Налог/Взнос | Формула | Периодичность |
|---|---|---|
| **УСН** | (Доходы − Расходы) × 15% | Ежеквартально (аванс), ежегодно (декларация) |
| **НДС** | НДС начисленный − НДС к вычету | Ежеквартально |
| **НДФЛ** (за сотрудника) | Зарплата × 13% | Ежемесячно |
| **Страховые взносы** (за сотрудника) | По тарифу | Ежемесячно |
| **Взносы ИП за себя** | Фиксированные + 1% с превышения | Ежегодно |

### 2.5. Модуль сверки

#### 2.5.1. Автоматические сверки

- ОФД (чеки) ↔ Банк (эквайринг) = **Сверка продаж**
- ЭДО (счета-фактуры) ↔ Банк (оплаты) = **Сверка закупок**
- Книга покупок ↔ Книга продаж ↔ КУДиР = **Сверка учёта**

#### 2.5.2. Отчёт о расхождениях

Система автоматически находит и показывает:
- Разницу между кассой и эквайрингом (комиссии)
- Оплаты без счетов-фактур (нельзя принять НДС к вычету)
- Поступления без чеков ОФД (продажа без чека или личный взнос?)
- Дубли операций

Каждое расхождение — интерактивная карточка с вариантами действий.

### 2.7. Модуль Б: AI-Агент («ИИ-Бухгалтер») — Agent-First Architecture

> **Подробная архитектура:** см. документ `АРХИТЕКТУРА_AI_AGENT.md`

#### 2.7.0. Архитектурный подход: Agent-First

Вместо набора отдельных endpoint'ов и cron-задач, система построена вокруг **единого AI-агента** с tool calling. Агент — центральный «мозг», который:

1. **Получает триггер** (вопрос пользователя, расписание, загрузка файла, событие)
2. **Анализирует контекст** через системный промпт с полным знанием бизнес-правил
3. **Вызывает инструменты** (tool calls) для работы с данными: расчёт налогов, классификация операций, формирование КУДиР, поиск аномалий
4. **Формирует ответ** пользователю на понятном языке
5. **Запрашивает подтверждение** для критических действий

**Цикл работы агента: Observe → Think → Act → Report**

```
Триггер (user/schedule/event)
    │
    ▼
┌─────────────────────────┐
│  AI Agent (LLM + Tools) │
│                         │
│  Системный промпт:      │
│  - Роль: ИИ-бухгалтер  │
│  - Правила УСН/НДС     │
│  - Контекст бизнеса    │
│                         │
│  Инструменты (tools):   │
│  - calculate_taxes      │
│  - classify_operation   │
│  - check_deadlines      │
│  - find_anomalies       │
│  - generate_kudir       │
│  - request_confirmation │
│  - send_notification    │
│  ...                    │
└─────────┬───────────────┘
          │
          ▼
    Ответ + действия + подтверждения
```

#### 2.7.1. Функции AI-агента

**🔍 Контроль баланса:**
- Сверка кассы и расчётного счёта
- Сверка ОФД и банковских поступлений
- Контроль наличия всех счетов-фактур
- Контроль дублей
- Контроль документального подтверждения расходов

**⚠️ Поиск ошибок и аномалий:**
- Необычно большие/маленькие суммы
- Продажи без чеков ОФД
- Оплаты поставщикам без счетов-фактур
- Расхождения НДС
- Пропущенные периоды
- Двойной учёт

**💡 Советы и рекомендации:**
- Напоминания о сроках
- Оптимизация налогов (уменьшение УСН на взносы и т.п.)
- Предупреждения о рисках (НДС к вычету > начисленного → возможна проверка)
- Анализ динамики выручки и расходов

**💬 Ответы на вопросы** (чат-интерфейс, простым языком):
- «Сколько я должен заплатить?»
- «Можно ли списать покупку в расходы?»
- «Что будет если не сдам декларацию вовремя?»

### 2.8. Модуль уведомлений и налоговый календарь

## 3. ПОДКЛЮЧЕНИЕ К ИИ (OpenRouter)

### 3.1. Почему OpenRouter

- Единый API — доступ к десяткам моделей
- Смена модели без переписывания кода
- Fallback: если одна модель недоступна — переключение на другую
- Оплата по факту использования

### 3.2. Распределение моделей по задачам

| Задача | Основная модель | Fallback | Температура |
|---|---|---|---|
| **Распознавание сканов (OCR)** | Claude 4 Sonnet | Gemini 2.5 Pro | 0.1 |
| **Классификация операций** | Claude 3.5 Haiku | Llama 3.1 70B | 0.0 |
| **ИИ-помощник (чат)** | Claude 4 Sonnet | Claude 3.5 Sonnet | 0.3 |
| **Сложные налоговые вопросы** | Claude 4 Opus | Claude 4 Sonnet | 0.1 |
| **Валидация, форматирование** | Claude 3.5 Haiku | Llama 3.1 70B | 0.0 |
