## КРИТИЧЕСКИЕ ПРОБЛЕМЫ

### 1. FK типы в оставшихся моделях (Mapped[str] вместо Mapped[uuid.UUID])

Миграция `001_initial_schema.py` создает все FK как `postgresql.UUID(as_uuid=True)`, но модели используют `Mapped[str]`. Это вызывает ошибку PostgreSQL: `operator does not exist: uuid = character varying`.

Файлы, которые ЕЩЕ НУЖНО исправить (заменить `Mapped[str]` на `Mapped[uuid.UUID]` + `UUID(as_uuid=True)` для FK полей):

- `backend/app/models/tax_calculation.py` — поле `user_id`
- `backend/app/models/tax_declaration.py` — поля `user_id`, `linked_calculation_id`
- `backend/app/models/tax_calendar_event.py` — поле `user_id`
- `backend/app/models/reconciliation_report.py` — поле `user_id`
- `backend/app/models/ai_chat_message.py` — поле `user_id`
- `backend/app/models/uploaded_file.py` — поля `user_id`, `linked_document_id`
- `backend/app/models/agent_event.py` — поле `user_id`
- `backend/app/models/agent_action_log.py` — поля `user_id`, `event_id`
- `backend/app/models/agent_confirmation.py` — поля `user_id`, `event_id`

Шаблон исправления:
```python
# БЫЛО:
user_id: Mapped[str] = mapped_column(
    ForeignKey("users.id", ondelete="CASCADE"),
    nullable=False,
    index=True,
)

# СТАЛО:
import uuid
from sqlalchemy.dialects.postgresql import UUID

user_id: Mapped[uuid.UUID] = mapped_column(
    UUID(as_uuid=True),
    ForeignKey("users.id", ondelete="CASCADE"),
    nullable=False,
    index=True,
)
```

### 3. get_db() в dependencies.py НЕ делает commit

В `backend/app/core/dependencies.py` функция `get_db()` не вызывает `commit()`:
```python
async def get_db() -> AsyncSession:
    async with async_session_factory() as session:
        try:
            yield session
        finally:
            await session.close()
```

А в `database.py` есть `get_async_session()` которая ДЕЛАЕТ commit. Но в dependencies используется другая функция.

Нужно исправить `get_db()`:
```python
async def get_db() -> AsyncSession:
    async with async_session_factory() as session:
        try:
            yield session
            await session.commit()
        except Exception:
            await session.rollback()
            raise
        finally:
            await session.close()
```

Либо использовать `get_async_session` из database.py вместо дублирования.

**Связанная проблема:** `documents.py` роутер использует `await db.flush()` вместо `await db.commit()` в confirm/reject/update. Если `get_db()` не делает auto-commit, данные НЕ сохраняются.

### 4. Отсутствуют API роутеры для counterparties и bank_accounts

## ПРОБЛЕМЫ FRONTEND-BACKEND СИНХРОНИЗАЦИИ

### 5. Enum mismatches между frontend и backend

**OperationStatus:**
- Frontend (`types/index.ts`): `'new' | 'classified' | 'confirmed' | 'rejected'`
- Backend (`enums.py`): `PENDING = "pending"`, `CLASSIFIED = "classified"`, `CONFIRMED = "confirmed"`, `RECLASSIFIED = "reclassified"`
- Проблема: frontend использует `new` и `rejected`, backend — `pending` и `reclassified`

**DocumentStatus:**
- Frontend: включает `'uploaded'` 
- Backend: НЕ имеет `uploaded`, имеет `uploading`

**DocumentType:**
- Frontend: включает `'unknown'`
- Backend: НЕ имеет `unknown`, имеет `other`

**DeclarationStatus:**
- Frontend: НЕ имеет `validation_error`, `signed`
- Backend: имеет `validation_error`, `signed`

Нужно синхронизировать `frontend/src/types/index.ts` с `backend/app/constants/enums.py`.

### 6. Frontend operationsApi.reclassify использует PUT, backend — POST

В `frontend/src/api/endpoints.ts`:
```typescript
reclassify: (id: string, category: string) =>
    apiClient.put(`/operations/${id}/reclassify`, { category }),
```

В `backend/app/api/v1/operations.py`:
```python
@router.post("/{operation_id}/reclassify", ...)
```

Нужно исправить frontend на `apiClient.post(...)`.

### 7. Frontend userApi.getMe вызывает /users/me, но после register/login

В `authStore.ts` после login/register вызывается `userApi.getMe()` который идет на `/users/me`. Это работает, но есть дублирование — `/auth/me` тоже возвращает пользователя. Не критично, но стоит унифицировать.

## ПРОБЛЕМЫ DOCKER / NGINX

### 8. Nginx в dev-режиме конфликтует с frontend dev-сервером

В `docker/nginx/nginx.conf`:
```nginx
location / {
    root /usr/share/nginx/html;
    index index.html;
    try_files $uri $uri/ /index.html;
}
```

Но в dev-режиме (`docker-compose.yml`) фронтенд работает как dev-сервер на порту 3000. Nginx пытается раздавать статику из `/usr/share/nginx/html`, которой нет.

Нужно для dev-режима проксировать на frontend:
```nginx
location / {
    proxy_pass http://frontend:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
}
```

### 9. Docker compose — backend не пробрасывает порт

В `docker-compose.yml` backend не имеет `ports:` секции. Доступ только через nginx. Это нормально для prod, но для dev может быть неудобно (нет прямого доступа к /api/docs).

Рекомендация: добавить `ports: ["8000:8000"]` в dev compose.

## ПРОБЛЕМЫ КОДА

### 10. auth_service.py делает commit внутри сервиса

`AuthService.register()` и другие методы вызывают `await self.db.commit()` напрямую. Если `get_db()` тоже делает commit — будет двойной commit. Нужно выбрать одну стратегию:
- Либо сервисы делают commit (и get_db НЕ делает)
- Либо get_db делает auto-commit (и сервисы используют flush)

Рекомендация: сервисы используют `flush()`, а `get_db()` делает auto-commit. Это стандартный паттерн.

### 11. PaginatedResponse использует `list[Any]` вместо Generic

В `schemas/common.py`:
```python
class PaginatedResponse(BaseModel, Generic[T]):
    items: list[Any]  # <-- должно быть list[T]
```

`items: list[Any]` теряет типизацию. Нужно `items: list[T]`, но Pydantic v2 с Generic требует особого подхода. Как минимум, для response_model в роутерах это не критично (FastAPI сериализует через model_validate), но стоит исправить.

### 12. Отсутствует frontend/.env.example

Нет файла `frontend/.env.example` с переменной `VITE_API_BASE_URL`. Сейчас API_BASE_URL захардкожен в `client.ts` как `/api/v1`, что работает через nginx proxy, но для standalone dev-режима может понадобиться полный URL.

### 13. Отсутствует core/logging.py (или он пустой)

В `main.py` импортируется `from app.core.logging import setup_logging`. Нужно проверить, что файл существует и содержит рабочую реализацию.

### 14. Отсутствует core/celery_app.py проверка

Celery worker и beat запускаются через `celery -A app.core.celery_app`. Нужно проверить, что этот модуль корректно настроен и импортирует все задачи.
